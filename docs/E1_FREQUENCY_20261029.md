# E1：「中段大燒前導棒」路線家族多常出現（2026-10-29）

**問題：** GLOBAL_ORACLE（[`GLOBAL_ORACLE_20261028.md`](GLOBAL_ORACLE_20261028.md)）在 `hyper_far` 找到一個管線拿不到的路線家族：
任務中段燒一發數百 m/s 的前導棒、再接終端棒，比管線多 0.21 分，差距全在燃料。管線搜尋的前導棒上界是 248 m/s、
拆棒器只拆終端棒，所以結構上碰不到它。這個家族只是 `hyper_far` 的特例，還是排位賽型題目常見？
這份的結果決定 oracle 要不要接進管線、接到什麼程度（規劃 §3.1：贏 ≥3 題 → 完整四臂比較；1–2 題 → 只接成附加候選；0 題 → 不接）。

**結論：**
1. **8 題隨機題裡 oracle 贏 3 題（`e1_r4` +0.099、`e1_r5` +0.083、`e1_r8` +0.178），落在「≥3 題」那一檔。**
   加上錨點 `hyper_far`（+0.212），10 題裡 4 題。
2. **贏的 3 題都是同一個家族：** 前導棒超過管線的 248 m/s 上界（`e1_r4` 805、`e1_r8` 1,130、`e1_r5` 254 m/s），
   放在任務前中段（t1 = 0.21–0.34 T_max），省下的都是燃料（總 Δv 少 7.6–16.3 m/s，抵達時刻差 ≤ 20 s）。
   同一題裡前導棒 ≤ 248 m/s 的 oracle 候選，拆完都跟管線差不多或更差（見前 10 名表），所以分差來自結構，不是 oracle 的拆棒或精修比較好。
   `e1_r5` 的前導棒只超過上界一點（254–331 m/s 的候選都贏），不是 `hyper_far` 那種 600 m/s 等級的大燒。
3. **oracle 的拆前排名不能拿來挑贏家：** 贏家在拆前排第 0、2、3、5 名。要接進管線，前 10 名都得精修＋拆棒，不能只拆第 1 名。
4. 其他 5 題：3 題平手（差 ≤ 0.007）、`e1_r2` 管線多 0.011；`e1_r7` **兩邊都沒有合法解**——
   拆前總 Δv 2.58–2.75 km/s（在 3 km/s 內），但管線 3 顆種子都留下一發 > 250 m/s 的棒（失格），oracle 前 10 名全部拆不出來。這是拆棒器的問題，不是燃料預算。
5. 附帶發現：**兩棒 oracle 的二體滑行（poliastro `vallado`）在特定輸入會無窮迴圈**，已在研究碼修好，見「oracle 卡死」。

## 題目

- **錨點**：`hyper_far`、`hyperbolic_smoke`（`configs/shared/`，計分覆寫同 GLOBAL_ORACLE）。
- **隨機題 8 題**：[`e1_gen_scenarios.py`](../scripts/research/e1_gen_scenarios.py) `--seed 20261029 --n 8`，設定檔在 `configs/research/e1/`。
  範圍取自題庫三個雙曲線情境：
  - B：SMA U(6700, 7400) km、ECC U(0, 0.01)、INC U(0, 60)°、RAAN／AOP／TA U(0, 360)°。
  - A：近地點 U(8000, 30000) km、ECC U(1.1, 1.6)、INC U(0, 60)°、RAAN／AOP U(0, 360)°；起點 TA = −f·ν∞，f U(0.82, 0.92)（錨點 f ≈ 0.89）。
  - T_max = 2 × 到近地點時間（題庫同一規則）；只收 20,000–200,000 s。能量下限 > 2,500 m/s 的重抽。10 抽收 8 題。
  - 計分：C_t = U(0.55, 0.70)·T_max、k_t = U(3, 4)/T_max、C_v U(1500, 2500) m/s、k_v U(0.0015, 0.0025)（錨點 C_t/T_max ≈ 0.62、k_t·T_max 3.25–4）。
  - 其他欄位照抄 `configs/shared/ranking_round.json`（MAX_BURNS [1, 2]、拆棒設定）。
- 規則全部：單棒 250 m/s、總 Δv 3 km/s、J2–J4、機動間隔 100 s。**題目是自己編的佔位題，不是官方題目。**

## 方法

- **管線（比賽當天設定）**：[`e1_anchors.json`](../sweeps/e1_anchors.json)、[`e1_random.json`](../sweeps/e1_random.json)，
  base 與 `global_oracle_contest` 相同（MAXITER 600、POPSIZE 20、NUM_THREADS 5、拆棒建議設定、`SPLIT_JACOBIAN=stm`），
  種子 0–2，每個行程各自的 `optimization.SEED`，`OMP/OPENBLAS/MKL/NUMEXPR_NUM_THREADS=1`，`sweep_params.py --slots 3 --timeout 3600`，只求解到拆棒。
  「合法」= 狀態 ok、未失格、Earth-safe、miss ≤ 5 km。
- **兩棒 oracle**：[`oracle_twoburn.py`](../scripts/research/oracle_twoburn.py)，粗網格 h = T_max/100、單棒網格 h/4、K = 10，前 10 名（去重）走
  `oracle_common.finalize_route`（前導棒等分 → `legalize_route` 拆棒＋joint NLP 精修 → 剔空燒 → 照交件規則重判）。每題跑 1 次（網格是確定性的）。
- **oracle 贏** = oracle 最好合法分數 − 管線最好合法分數 ≥ 0.05。
- 程式：`origin/codex/global-oracle` `1f6c739`（= Master `fb0ff12` + 研究碼），加本分支的 oracle 修正。
- 機器：Corn（Ryzen 7 5800X，8 核 16 緒，WSL2）。管線跟 oracle 不同時跑。

## 錨點重現

- 管線：`hyper_far` 3 顆都是 82.4327、`hyperbolic_smoke` 3 顆都是 86.7847，跟 GLOBAL_ORACLE 相同。
- oracle `hyper_far`：步長 h = T_max/100 = 1,625.7 s 得 **82.6445**（兩次，修正前後相同）；用上一輪的 h = 1,626 s 重跑得 **82.6473**，逐位元重現上一輪。
  0.3 s 的步長差讓網格點全部平移，前 10 名換了一批，最好的分數差 0.003。**所以 oracle 單次的分數有 ~0.003 的網格雜訊**，比 0.05 的贏線小一個數量級。
- oracle `hyperbolic_smoke`：86.7851（5 棒、639.3 m/s），比管線高 0.0003，等於平手。

## oracle 卡死（已修）

第一次跑 `hyperbolic_smoke`（h = 400 s）的兩棒網格 2 小時逾時。逐列、逐格縮小後定位到 (t1, t2, t3) = (4,000, 5,200, 10,800) s、dv1 = 0 起點的 Nelder–Mead：
poliastro `vallado` 的 Newton 迭代在這組雙曲線輸入發散成 NaN，NaN 進 `stumpff_c2/c3` 的級數分支 `while res + delta != res`（NaN 永遠不等於自己）就不會停。
`oracle_twoburn.py` 改用逐行複本 `vallado_safe`：psi 不是有限值就回傳 NaN（該格視為不可行）。2 萬組隨機輸入與原版逐位元相同；修正後 smoke 74 s 跑完。
**GLOBAL_ORACLE 記載的「h = 250 s 跑 5 小時沒結束、判斷是負載不均」應該也是這個**，負載不均的修法（配對隨機分派）本身沒錯，但當時沒踩到這格只是運氣。
產品程式（`src/`、`main.py`）沒用到 `vallado`，不受影響。

## 限制

- 隨機題只有 8 題，「3/8」的95% 信賴區間很寬（Clopper–Pearson 約 9%–76%）。結論只到「這個家族不是 `hyper_far` 特例、常見到值得接」，不到「出現率是多少」。
- 題目範圍是自己定的；真題的 B 軌道、相對傾角、T_max 規則都還不知道。
- oracle 每題只跑一次，有 ~0.003 的網格雜訊（見錨點）；管線是 3 顆種子取最好，種子間差異見 `docs/e1_frequency/<題目>.json`。
  贏的 3 題差距 0.08–0.18，都遠大於這兩種雜訊。
- `e1_r7` 這種「拆前在 3 km/s 內、但拆不出合法解」的題目，這次沒查原因。
