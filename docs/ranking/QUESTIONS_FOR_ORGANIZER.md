   驗證時是沿用我們 Script 裡的這些設定，還是用主辦單位自己的？外星人太空船 A 也受阻力與輻射壓嗎？
3. **排位賽範例題目**：能否在賽前提供一組範例（題目 Script、T_max、計分參數與一組參考解）？
   數值跟正式題目不同也沒關係，主要用來確認格式與驗證設定。
4. **金／銅牌賽的安全空域**：是否只看逃脫方第 6 回合結束時的半長軸 a？還有沒有其他條件？

   最好連同一組範例題目（雙方初始狀態、安全空域、ΔV_lim、R_cap、T_round）？

## 為什麼問這幾題（寄的時候不附）

- **1**：決定當天流程。繳交格式影響腳本產生器要不要改成套主辦的題目 Script；禁不禁網路決定能不能把計算丟回 Corn。
- **2**：B 在低軌停留 10 h 的任務，阻力與輻射壓參數不確定時攔截點散布 p90 約 7.6 km，超過 5 km 門檻
  （[全攝動落差研究](../research/PERTURBATION_GAP_20261019.md)）。驗證沿用我們的設定，這個不確定性就消失。
  11-01 版規則把 A 改成「僅受外界力場影響」，A 受不受阻力也影響攔截點。
- **3**：初賽範例幫我們抓到計分參數單位陷阱與一個誤判撞地球的 bug；排位賽換成全攝動，沒有官方對照就無法在賽前驗證。
- **4**：逃方策略的硬條件（`ODC_GMAT_DRL/agents/final_evader.py`）。若還有其他條件，躲方必勝的結論（E27–E29）要重測。
- **5**：`copilot.py final` 已能吃 GMAT 報表、CSV、JSON、純文字，有範例就能在賽前確認一次。

## 開賽時問工作人員（不寄）

這些答案不會改變做法，工具已用保守設定處理；當天問清楚，照答案填設定或確認即可。

| 問題 | 工具現況 |
|---|---|
| 排位賽 T_max 直接給秒數嗎？任務邊界是地心距離還是高度？ | `odc.py tmax` 兩種都能算 |
| 計分參數 `k_t, C_t, k_v, C_v` 的單位（初賽是 km/s 制） | `odc.py scoring` 換算 |
| 排位賽：第一次機動跟 t = 0 要不要隔 100 s？Δr_min 有沒有內插？穿越地球的門檻？ | 照最嚴格的解讀 |
| 金牌賽：兩艘初始 epoch 不同時，第 1 回合是否從較晚的 epoch 開始？ | `game/initial_state.py` 照這個假設 |
| 金牌賽：提交的 Δv 照提交位數還是四捨五入到兩位執行？ | 印 4 位小數並用印出的值重驗，兩種都安全 |
| 金牌賽：攔截判定的取樣、撞地用的地球半徑、μ | 引擎連續偵測；最近距離常有上百 km，差異不影響 |

## 刻意不問（會透露我們的分析）

- **兩個角色的勝算有沒有校準**、**安全空域一定到得了嗎**：實測正式賽制下逃方幾乎必勝，唯一例外是安全空域到不了
  （`ODC_GMAT_DRL/docs/EXPERIMENTS.md` E27–E29）。這兩題一問，等於公開提醒其他隊。角色選擇器現場會直接判斷。
