## 1. 現在的流程

`main.main()` 的求解主幹（2026-09-22 現況）：

```
run_seed_portfolio(config)                       # 可選：跑 N 顆 SEED、§6 留拆後最高（預設 N=1 關）
  └─ _solve_pipeline(config)  ×N
       ├─ run_study_over_revs(config)            # REVS 集成：REVS=0 與 LAMBERT_MAX_REVS 各跑一趟，§6 取優
       │     └─ MissionOptimizer.run_study()     # L-SHADE ×MAXITER×POPSIZE，MAX_BURNS=[1,2,3] 平行，+ 種子精修(SLSQP)
       ├─ primer_guided_research(...)            # C2：對贏家算 primer；|p|>1 才開 SPLIT_AWARE+插棒種子重搜
       └─ legalize_violating_winner(...)         # HAP-67：違規大棒 → 拆成合法多棒
             └─ burn_splitter.legalize_route(..., n_span=1, maxiter=80)
                   ├─ legalize_intercept()       # 貪婪拆終端 → 能量下限段數 nseg0（平均分 + 每段重解 Lambert）
                   └─ for nseg in [nseg0 .. nseg0+n_span]:     # 含端點：n_span=1 → 試 nseg0 與 nseg0+1
                          候選 = { greedy 暖啟本身, joint_nlp_split(x0, N) }   # 兩者都評、取 feasible 最高
                                   # joint_nlp_split：SLSQP、maxiter=80、有限差分梯度、目標 = -calculate_score
  → Earth-safe 閘門 → GMAT 無頭驗證（一般版 DC + 固定燃燒繳交版）
```

拆棒器（`src/burn_splitter.py`）的兩層本質：
- **段數 N**：由 `legalize_intercept` 的能量下限 `nseg0` 決定（`ceil(大棒Δv / cap)` 那類），
  外層 `legalize_route` 在 `[nseg0, nseg0+n_span]`（**含端點**，[burn_splitter.py:298](../src/burn_splitter.py)
  `range(nseg0, nseg0+n_span+1)`）掃——預設 `n_span=1` 已經會試 nseg0 與 nseg0+1。
- **給定 N 的拆法**：`joint_nlp_split` 用 **SLSQP**（有限差分梯度、maxiter=80）把「t0 + 各段
  coast + 各段 ECI Δv」聯合優化，命中 A(T) / cap / 近地點當約束，目標最小化 −score（≈總 Δv）。

## 2. 現在流程的問題

拆後那 0.007~0.01 的飄動 + 拿不到更好解，是**三個獨立成因**疊在一起，必須分開治：

### 問題 ①（系統性缺口？）：7 棒解為什麼走不到——兩種可能，待 V1 判別
- **初稿誤判更正**：`legalize_route` 的段數迴圈含端點，main 端 `legalize_violating_winner`
  傳的 `n_span=1`（[main.py:525](../main.py)）**已經會試 nseg0 與 nseg0+1**。所以「段數寫死在
  nseg0、結構上到不了」不成立。
- 而且 §0 的 7 棒解來自 C2 重搜（前導棒 3→4）跳到的**另一條路線家族**，不是 88.3219 路線多拆
  一段。所以「滿預算拿不到 98.319」有兩種解釋：
  - **(a) 拆棒器側**：88.3219 路線的 nseg0+1（甚至 +2）其實更好，但 SLSQP 沒調到位、輸給 nseg0，
    或 nseg0+1 的 greedy 暖啟本身不可行 → 修拆棒器（掃更寬 / 更好的 NLP / 凸）有用。
  - **(b) 搜尋側**：7 棒解屬於另一條路線，88.3219 路線怎麼拆都到不了 → 要改的是**搜尋如何
    到達那條路線**，拆棒器改再多都沒用。
- (b) 若成立，C2 的盲點就是關鍵：C2 的觸發門檻是「拆棒**前** primer optimal-ish」。88.3219 作為
  2 棒攔截**本身就是燃料最優**（max\|p\|=1.000），primer 正確地說「不用加節點」——但**拆棒後**
  的最優可能來自多一個前導節點的路線。**拆棒前最優 ≠ 拆棒後最優**，C2 讀的是前者，天生看不到後者。

### 問題 ②（抖動，拆前同分的路線拆出不同分）：先確認抖動的來源
- `joint_nlp_split` 是 SLSQP + 有限差分梯度 + maxiter=80 → **局部最優、對暖啟敏感**。C1 study §5
  也點名：現在的拆棒器「平均分 + SLSQP」**既不是 primer 最優、也不是 bounded-impulse 最優**。
- **但**：同一個輸入、BLAS 已 pin 的情況下，SLSQP 應該逐位元可重現——它本身不是隨機的。§0 三顆
  SEED 的拆前分數只在**四位小數**上相同（88.3219），傳進 `legalize_route` 的 t0 / coast / 前導 Δv
  很可能有微小差異。所以抖動可能是**上游給了近乎同分、但不同的輸入 → SLSQP 對暖啟敏感而放大**，
  而不是拆棒器自己在飄。這個區分決定要修哪裡（V2 第一步）。
- 另兩個可疑點：(i) SLSQP 是否常因跑滿 `maxiter=80` 才停（`res.status == 9`）——若是，單純加大
  maxiter 就可能大幅縮小散布；(ii) 多圈傳播上的有限差分梯度雜訊（[burn_splitter.py:310](../src/burn_splitter.py)
  的註解已承認 SLSQP 會把可行暖啟推出邊界）。

### 問題 ③（跑太久）：用蠻力掩蓋 ①②，且被機器睡眠灌水
- seed-portfolio「跑 N 顆留最高」本質是**用重複計算去繞過抖動 ②**——治標、很貴。
- REVS 集成 ×2：§0 三顆 SEED 兩趟 REVS **都收斂到同一個 88.3219**，此幾何下邊際價值近乎 0。
- 實跑 wall-clock **7h24m**，但時間軸顯示大半是**這台 Mac 傍晚/半夜睡著/降頻**（正常 3 棒案例
  ~5.6 分，SEED=1 的 3 棒案例卡了 4h41m 然後下一趟又瞬間恢復正常）——真實 CPU 計算約 **~2h**。
  睡眠是環境問題（keep-awake / 雲端），但「就算不睡也要 ~2h」仍太久，根因就是 ①②的蠻力繞過。

**一句話**：抖動（②）和跑太久（③ 靠 portfolio 繞過 ②）**大概率同源於 SLSQP 拆棒器對暖啟的敏感**，
但要先排除「上游輸入不同」；拿不到 7 棒解（①）可能是拆棒器側也可能是搜尋側，V1 判別前不要先假設。

## 3. 要驗證什麼（Phase 0，先 de-risk，不改主管線）

在投入凸優化改寫前，先用**便宜實驗**確認問題真實、量化大小、確認凸解可行：

執行順序：**V2 前半 → V1 → V2 後半 → V3**（V2 前半幾乎零成本、且決定抖動該去哪修）。

- **V1：7 棒解走不到，是拆棒器側 (a) 還是搜尋側 (b)？含奇偶假說**
  1. 拿 §0 滿預算的 88.3219 勝出路線，**先記錄現行管線**（`n_span=1`）nseg0 與 nseg0+1 各自的
     greedy 暖啟分數、NLP 分數、feasible、SLSQP 結束狀態——現行到底是哪一個贏、輸的那個輸在哪。
  2. 再把 `n_span` 開到 3+（nseg0 .. nseg0+3），看分數是否隨段數改善。
  3. 判讀：88.3219 路線某個段數 ≥ 98.319 → **(a) 成立**，修拆棒器有用（先看 nseg0+1 是否只是
     NLP 沒調好；再看是否需要更大 n_span）。所有段數都明顯低於 98.319 → **(b) 成立**，7 棒解是
     另一條路線，要改的是搜尋/C2（見問題 ①），本計畫的 A/B 檔都不會把它帶回來。
  4. 另外把煙霧測試那條 7 棒路線過 GMAT，確認 98.319 本身**可重現且 GMAT 收斂**，否則 ① 整個不成立。
  - **奇偶（parity）假說（2026-09-23，使用者提出）**：拆**終端那發**大棒時，**奇數段**可讓一發
    正好落在錨點 P（單脈衝最省點）、其餘對稱分佈於 P±k·100s，主要那發不偏離最優；**偶數段**
    則沒有任何一發能落在 P、全部被 100s 間隔推離錨點。→ 假說：**終端拆分取奇數段系統性更省**。
    §0 的一個數據點（6 棒偶 vs 7 棒奇，奇的贏）與之一致，但 n=1 不足證。**V1 明確分「終端拆分
    段數」的奇/偶兩組比**（注意：要比的是**終端拆分段數**的奇偶，不是總棒數——總棒數混進了與
    此對稱性無關的前導棒）。若看到穩定 parity → 可當「終端拆分優先取奇數段」的經驗規則。
    **強度警戒**：「P±k·100s」是 greedy 暖啟的幾何（間距剛好 = `min_coast`）；joint NLP 把 coast
    當自由變數、約束只是**≥** `min_coast`，偶數段可以放在 P±50s、P±150s…，偏離量只是比奇數段
    大一點，並非「全部被推離」。所以預期效應是**二階小量**，不是結構性必然。其他反例：約束不對稱
    於 P（cap 咬點/Earth-safe/T_max 邊界）、時間項 `k_t/C_t`、大 N 洗掉邊際好處。**本假說只在 V1
    順便分組看，不作為 A 檔的依據**；若 B 檔（凸、時間網格）成立，奇偶會被自動處理，不需此規則。

- **V2：抖動 ② 的來源與量級**
  - **前半（先做，幾乎零成本）**：把 §0 三顆 SEED 傳進 `legalize_route` 的參數（t0、前導 Δv、
    前導/終端 coast、target）dump 出來**逐位元比對**，同時記錄每次 SLSQP 的 `res.status` / `nit`。
    - 輸入不同 → 抖動來自上游，拆棒器是「對暖啟敏感」而非「自己在飄」；
    - 輸入相同卻拆出不同分 → 真正的非確定性，另外抓（BLAS pin 是否生效等）；
    - 常見 `status == 9`（跑滿 maxiter）→ 先試 maxiter 80→300，看散布是否就此縮小。
  - **後半**：對**同一條路線、同一段數**，對暖啟加小擾動跑 N 次 `joint_nlp_split`，量分數散布。
    預期看到 ~0.008 級散布且與暖啟相關 → 證實是 SLSQP 局部最優。

- **V3：凸公式的可行性與正確性（凸改寫的前置）**
  對**一個已知案例**（如 88.3219 路線的終端大棒）用 bounded-impulse convex formulation
  （arXiv:2101.07403 / 2510.03423）解一次，比對：(a) 總 Δv 是否 ≤ 現行拆棒器最佳；(b) 跨次
  執行是否**完全確定性**；(c) 座標系/單位/時間網格是否跟我們的 ECI/km/s 對得上（C1 study §8 的
  開放風險）。
  - **現實預期**：我們的動力學含 J2–J4 + 多圈傳播，凸公式要在參考軌跡上用 STM 線性化，實作上是
    **循序凸規劃（SCP）**：每個凸子問題是全域最優，但對原非線性問題**仍是局部最優**；分數裡的
    時間項與命中約束也非凸。所以成功標準是「**比 SLSQP 穩、散布更小、確定性**」，不是「全域最優」。
  - **時間網格的附帶好處**：以間距 = `min_coast` 的網格在每個格點放一個可為零的脈衝、用 sum-of-norms
    目標，凸解會讓多數格點歸零——**段數與奇偶自動決定**，不必外層掃 N。脈衝時刻仍受網格與
    參考軌跡限制，大範圍的時刻/路線選擇仍靠 primer + 外層搜尋。

## 4. 要改什麼

依 Phase 0 結果分兩檔：

**A. 立即、低風險（依 V1/V2 前半結果擇一或並用）**：
- **A1（V2 前半顯示常跑滿 maxiter）**：`joint_nlp_split` 的 maxiter 80 → 300（或到收斂），
  必要時對暖啟做少量多起點、取 feasible 最高。成本秒級。
- **A2（V1 判定 (a) 且更多段數有益）**：main 端 `legalize_violating_winner` 的 `n_span=1`
  （現況已試 nseg0、nseg0+1）→ 2~3，取 §6 最高。每多一段多一次 joint NLP（~秒級），比 portfolio ×N 便宜。
- **V1 判定 (b)**：A 檔對 7 棒解無效，改開新題目處理「搜尋如何到達拆後更優的路線」（C2 改讀
  拆後分數等），不在本計畫範圍。
- ~~可能單獨就 +0.007~~：初稿的預期基於誤讀，**收回**，改以 V1 實測數字為準。

**B. 治本（若 V3 成立）**：新增 **凸 bounded-impulse（SCP）拆棒器**取代/並存 SLSQP。
- 新模組 `src/convex_splitter.py`：給定路線骨架（時刻/幾何由 primer + 搜尋定），在 `min_coast`
  間距的時間網格上對各脈衝大小/方向解凸子問題、SCP 迭代 → **確定性、比 SLSQP 穩**（對原非線性
  問題仍是局部最優，見 V3）。
- 預期收益：**抖動 ② 大幅縮小**（確定性、對暖啟不敏感）＋**段數/奇偶自動決定**（多餘格點歸零）。
  前提是 V2 證實抖動主要來自拆棒器對暖啟的敏感；若來自上游輸入差異，凸也只能縮小放大效應。
- 連帶 **③**：抖動變小 → seed-portfolio 的蠻力價值下降，N 可降回 1、REVS 集成也可重評 →
  跑時間下降。

**C. 流程瘦身（B 成功後）**：
- `SEED_PORTFOLIO_N` 預設維持 1；把它從「掩蓋抖動的工具」降級成「純探索多起點」的可選項。
- 重評 `REVS_ENSEMBLE`（此題型兩趟同解）與 `MAXITER=2000`（基礎搜尋早收斂）是否過頭。

## 5. 要怎麼做（分階段，每階段可獨立驗收）

- **Phase 0（驗證，~半天）**：依序 V2 前半 → V1 → V2 後半 → V3。產出：一份 AB 數據 + GMAT 驗證，
  判定抖動來源、7 棒解是 (a)/(b)、A 檔哪一項值得、B 檔可不可行。**先做 V2 前半**（幾乎零成本、
  決定抖動該修上游還是拆棒器）。
- **Phase 1（A 檔，依 Phase 0 結果）**：A1 maxiter/多起點、A2 `n_span` 掃寬，§6 選最高，加回歸
  （同路線拆出的分數不低於現況）。GMAT 複驗勝出解。低風險、快。
- **Phase 2（B 檔原型，若 V3 過）**：`src/convex_splitter.py` 獨立原型（cvxpy 或等價），
  對 `docs/solutions/` 封存解 + 88.3219 路線做 AB（vs `legalize_route`），全部 **GMAT 驗證**。
  依賴：新增 cvxpy（進 pyproject）。
- **Phase 3（B 檔接線）**：旗標 `strategy.SPLITTER=nlp|convex`（預設 nlp 直到證明），
  接進 `legalize_violating_winner`；`tests/` 補凸拆棒回歸（確定性斷言：同輸入跑兩次逐位元同分）。
  證明穩定後翻預設。
- **Phase 4（瘦身）**：凸確定性到手後，量測 N=1 + 關/簡化 REVS 集成的跑時間與分數，定案降級。

**風險 / 注意**：
- 凸攔截公式的末端條件（位置命中、末端速度自由、零速度成本）要對——**不能套 rendezvous**
  （同 C1 攔截橫截條件的坑）。
- 時刻非凸：凸只解「給定時刻的脈衝」，時刻仍靠 primer + 搜尋。多圈 Lambert 幾何的非凸性不進凸層。
- 所有 AB 對照前必 pin BLAS（[[odc-blas-nondeterminism]]），否則分不清是改動還是雜訊。
- Earth-safe（近地點約束）要進凸模型的約束集，別讓凸解鑽地球（初賽失格線，見 [[odc-collision-check-verification-gap]]）。

## 6. Phase 0 結果

### V2 前半（2026-09-23）：抖動來源 = SLSQP 被 maxiter=80 截斷 → 可行性抽籤

**輸入比對**（`outputs/run.log`，§0 那次實跑）：三顆 SEED 採用的拆前路線**不一樣**。都是
「Burn1 1498 m/s @t=0 → **Δv=0 的空燒** → 終端 4691 m/s @2370.9s」，但空燒時刻不同：
SEED0 **1270.8s**（採用 REVS=4 那趟）、SEED1 **1289.7s**（REVS=0）、SEED2 **1371.8s**（REVS=4）。
DE 在「空燒放哪都同分」的平坦方向上隨便停，拆前分數完全看不出差別。空燒被
`legalize_violating_winner` 當成一發前導棒傳進 `legalize_route`，所以 joint NLP 的暖啟和維度都跟著變。

**控制變因重跑**（腳本在 session scratchpad `v2_first_half.py`；用 log 的 VNB/時刻重建路線，
target 取 A(T) 正中心、BLAS pin 單執行緒；重建有四捨五入誤差，絕對分數與實跑差 ~1e-4，但**每組內
逐位元可重現**）：

| 空燒時刻 | maxiter=80 拆後（N） | maxiter=300 拆後（N） | maxiter=1000 拆後（N） |
|---|---|---|---|
| 1270.8（SEED0） | 98.3121（6） | 98.3174（7） | 98.3174（7） |
| 1289.7（SEED1） | **98.3020**（6，退回 greedy） | 98.3173（6） | 98.3174（7） |
| 1371.8（SEED2） | **98.3020**（6，退回 greedy） | 98.3173（7） | 98.3174（7） |
| 無空燒 | **98.3020**（5，退回 greedy） | 98.3175（6） | 98.3175（6） |
| **散布** | **0.0101** | **0.0002** | **0.0001** |
| 8 次 NLP 總耗時 | 100s | 332s | 680s |

**機制（逐候選紀錄）**：
1. maxiter=80 時 **每一次 SLSQP 都是 `status=9`（跑滿迭代上限被截斷）**，沒有一次收斂。
2. 截斷點的 NLP 解分數其實都在 ~98.312，但約束**擦邊違反**（miss 3.498/3.501 vs 容許 3.5、
   maxdv 1498.00x vs cap 1498.00，都差在 1e-3 量級）→ `feasible=False` 被丟掉 →
   只剩 greedy 暖啟保底（98.3020）。**能不能「剛好停在可行側」就是抽籤**，與空燒位置、暖啟細節
   混沌地相關——這就是 §0 的 98.3121 vs 98.3037。
3. `max_revs` 0 vs 4 對拆棒結果**零影響**（逐位元相同），REVS 集成的 tie-break 不是原因。
4. maxiter=300：散布從 0.0101 縮到 0.0002，分數全面上移到 **98.317x**，**高於初賽冠軍 Team15
   的 98.3162**，也跟 HAP-47 PoC 的 98.3177 一致。但多數仍是 `status=9`、仍有候選擦邊 infeasible，
   只是更接近收斂。耗時：每次 joint NLP ~12s（80）→ ~40s（300）。
5. maxiter=1000：**8 個候選全部 feasible**，6/8 真正收斂（`status=0`，nit 236~823），另 2 個跑滿
   1000 但也可行；散布再縮到 **0.0001**（98.3174~98.3175）。每次 NLP ~85s，管線每顆 SEED 拆棒
   2 次 NLP → ~3 分鐘，仍遠低於 seed-portfolio ×N 的成本。**收斂所需迭代數 236~823 → 80 差了一個數量級**。

**對問題 ① 的啟示**：maxiter=300 時空燒路線的最佳解有 7 棒（nseg0+1）也有 6 棒，差 <0.0002——
「6 棒 vs 7 棒」不是關鍵，**NLP 有沒有收斂才是**。§0 煙霧的 98.3190 是否屬另一條路線（(b)），
仍待 V1 第 4 步 + GMAT 確認；但滿預算管線拿不到 98.317 的主因已經確定是 ②。

**對計畫的修正**：
- **A1 升為最優先、幾乎確定值得做**：maxiter 80 → **1000**（收斂需 236~823 次；300 仍有擦邊丟解），外加
  **擦邊可行性修復**——在 NLP 內用略緊的約束（cap−ε、miss_tol−ε）求解、出來再用真實約束判，
  或對擦邊解做一步投影，避免「98.317 的解因 1e-3 km 擦邊被丟掉、退回 98.302」。
- seed-portfolio「跑 N 顆留最高」在 A1 之後大概率可退役：它在做的事就是替截斷的 SLSQP 多抽幾次籤。
- B 檔（凸）優先度下降：A1 若把散布壓到 1e-4 級，凸的邊際價值要重新評估。
- 空燒棒：DE 產出的 Δv≈0 空燒被當成前導棒傳給拆棒器，是這條輸入差異的源頭。可考慮在
  `legalize_violating_winner` 前先剔除 |Δv|≈0 的空燒棒，讓拆棒器輸入不再受 DE 平坦方向影響
  （但 maxiter=300 的「無空燒」與有空燒同分，所以這是可重現性加分、不是分數來源）。

### A1 實作 + 真實路線驗證（2026-09-23）

**改動**（`src/burn_splitter.py`、`main.py`）：
- `joint_nlp_split` / `legalize_route` 的 maxiter 預設 80 → **1000**；main 不再寫死 80。
- SLSQP 對略緊的約束求解（cap −0.02 m/s、miss −5 m、近地點 +1 m），出來仍用真實約束判 feasible。
- 新增**拆棒前贏家存檔**：每次完整跑自動寫 `outputs/winner_presplit_seed<SEED>.json`；
  `main.py --from-winner <檔>` 跳過搜尋、直接接拆棒 + 產腳本 + GMAT。改拆棒器從此不必重跑搜尋。

**驗證**（contest 幾何、SEED=0、單顆、REVS 集成關、BLAS pin）：先完整跑一次（maxiter=80，25 分鐘）
當基準並存檔，再用同一個存檔 `--from-winner` 重播 A1——**同一條路線逐位元相同的輸入**：

| | 拆後分數 | 棒數（實燒） | 總 Δv | GMAT 一般版(DC) | GMAT 固定燃燒版 | 耗時 |
|---|---|---|---|---|---|---|
| 基準 maxiter=80 | 98.3121 | 6（5） | 6,188.4 | ✅ 命中/收斂/合規 Δr 3,500m | ✅ | 拆棒 ~30s |
| **A1** | **98.3174** | 7（5） | 6,189.1 | ✅ 命中/收斂/合規 Δr 3,495m | ✅ 可交 | 重播全程 3.7 分 |

- 基準重現了 09-22 SEED0 的 98.3121（空燒同在 1270.8s）——存檔/重播鏈與原管線一致。
- A1 **+0.0053**，GMAT 過，且**高於初賽冠軍 Team15 的 98.3162**；Python vs GMAT Δr 差 0.28m。
- 「7 棒」裡有 **2 發 Δv=0**：DE 留下的空燒（B1）和 NLP 把多的終端段壓到 0（B6，也是 DC 打靶那發）。
  **實際燃燒 5 發**（1498×4 + 197 m/s）。→ 奇偶假說在此例不適用：最優解的實燒數跟 6/7 段無關，
  NLP 自己會把多餘段歸零（凸方案要的「自動定段數」SLSQP 收斂後已部分做到）。
- 待辦（小）：繳交腳本裡的 Δv=0 Maneuver 無害（間隔合規、GMAT 過），但可在產腳本前剔除以免
  評審困惑；B6 是 DC 打靶棒，剔除時要把打靶角色移給最後一發實燒。

**對計畫的更新**：問題 ②（抖動）主因已修；A2（`n_span` 掃寬）與 B（凸）暫緩，先用 A1 後的
管線量 seed 間散布（`--from-winner` 讓這件事只需「每顆 SEED 一次搜尋」）。seed-portfolio 預設
維持關，REVS 集成是否關閉待多幾何確認。
