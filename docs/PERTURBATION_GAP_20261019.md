# 排位賽全攝動落差：同一組脈衝在官方攝動模型下還打不打得中（2026-10-19）

**問題。** 求解器用 J2–J4（初賽解用點質量），排位賽官方驗證開 EGM96 20×20、固體與極潮汐、
NRLMSISE00 阻力、日月第三體、SRP、相對論（[規則摘要](RANKING_ROUND_RULES_20261006.md)）。
把現成解的脈衝（時間與 VNB Δv 一位不改）放進 GMAT 全攝動模型重播，看最小距離、攔截時刻和
Earth-safe 會差多少，以及要不要在比賽當天加一步重瞄準。

**工具：** [`scripts/research/perturbation_gap.py`](../scripts/research/perturbation_gap.py)（只呼叫 GmatConsole，不動 `src/`）。
產物在 `outputs/research/perturbation_gap/`（git 忽略），圖在 [`figures/perturbation_gap_mc_20261019.png`](figures/perturbation_gap_mc_20261019.png)。

## 結論

1. **攝動的影響取決於任務多長。** 只看 J2–J4 → 全攝動，攔截點位移在 1.6 h 以內的任務是
   **0.5–1.3 km**，5.5 h 是 **2 km**，22.6 h 的 hyper_far 是 **263 km**。短任務的位移幾乎都來自
   EGM96 比 J2–J4 多的田諧項；長的雙曲線任務主要來自**日月第三體**（hyper_far 單項 297 km）。
   潮汐與相對論都 ≤ 20 m。標稱參數下，阻力加 SRP 在短任務 ≤ 40 m，hyper_far 約 2 km。
   Earth-safe 不受影響，五個解的最低高度都沒變。最近點時刻只差 0.1–3 s，hyper_far 晚 62 s，
   對 T_team 分數的影響可以忽略。
2. **我們瞄 Δr ≈ 3.5 km，離 5 km 只剩 1.5 km 的餘裕。** 用 J2–J4 設計的三個解直接放進全攝動：
   official_sample 3.45 → 3.91 km、hyperbolic_smoke 3.49 → 3.91 km 還在門檻內；hyper_far
   3.41 → **111 km**，距離項少拿 32.7 分。smoke 在只開 EGM96 時是 5.71 km，是日月項剛好往回拉
   才過關，不能當成安全。兩個點質量設計的初賽解差 57–69 km，但那是初賽官方模型留下來的，
   現行預設 `GRAVITY_DEGREE=4` 不會再這樣；把它們先在 J2–J4 下重瞄準再放進全攝動，只剩
   0.16 km 和 1.13 km。
3. **阻力與 SRP 參數不確定的影響，只在 B 長時間停在低軌時才大。** 質量 100–2000 kg、面積
   1–20 m²、Cd 2.0–2.4、Cr 1.0–1.8 各抽 60 組，四個解的攔截點相對標稱值的散布 p90 ≤ 0.18 km。
   hyper_far 的 B 先在 610 km 等了 10.5 h，散布中位 1.4 km、p90 7.6 km、最大 12.9 km，
   跟 B 的 Cd·A/m 相關係數 0.93。
4. **重瞄準有效又便宜，前提是用 B 平面瞄準。** 在全攝動加標稱參數下用 GMAT DifferentialCorrector
   改一棒，只消掉垂直於相對速度的兩個分量（B 平面）：所有解、所有試過的棒都在 2–6 次迭代內收斂。
   J2–J4 設計的解要多花的總 Δv 是 **0.04–2.5 m/s**，hyper_far 是 **−0.4～+4.6 m/s**。
   現有腳本的 DC 做法是要求預定時刻位置對齊，在 hyper_far 會多花 272 m/s，最後一棒變成 361 m/s，
   排位賽直接失格。重瞄準後再做蒙地卡羅，命中率是 100%；hyper_far 是 94%，三組沒中的都是
   B 的 Cd·A/m ≥ 0.12 m²/kg（標稱值 0.023 的 5 倍以上）。
5. **比賽當天的流程要加一步「全攝動 B 平面重瞄準」。** 做法見最後一節。另外要問主辦單位：
   太空船參數、SPADFile、任務曆元，以及驗證程式是否沿用我們腳本裡的 `DryMass/Cd/Cr/面積`。

### 模型與 GMAT 設定

- A 和 B 用同一個 ForceModel、同一次 `Propagate` 傳播。另外跑了一組「A 只受重力」的版本，
  因為規則寫 SC_Alien「僅受重力場影響」。
- 全攝動：`EGM96.cof` degree/order 20（GMAT R2026a 的 `data/gravity/earth/` 裡有）、
  `TideModel = 'SolidAndPole'`、`PointMasses = {Sun, Luna}`、`RelativisticCorrection = On`、
  `SRP = On`，阻力用 `NRLMSISE00` 搭配 CSSI 歷史太空天氣檔。
- 積分器是 RK89，Accuracy 1e-12，跟現有腳本相同。MaxStep 從 2700 s 收到 60 s，讓每步輸出的
  報表可以做 Hermite 內插找最近點。d_min 是在 [0, 預定攔截 + 600 s] 內找的最小值，先用
  1 s 解析度掃一遍，再細化到毫秒級；Earth-safe 取攔截前 B 的最低高度。
- 曆元沿用初賽腳本的 `TAIModJulian 21545`，也就是 2000-01-01 12:00。那時接近太陽極大期，
  阻力算是偏高的一側。

### 跟規則不一樣的地方

| 規則 | 這裡的做法 | 影響 |
|---|---|---|
| 阻力、SRP 用 SPADFile | 主辦單位的 `.spo` 沒公布。蒙地卡羅用球形模型（Cd、Cr、面積、質量） | 在 GMAT 實測，`SphericalModel.spo`（8.945 m²）等於球形模型的 **Cd = 1、Cr = 1**：LEO 一天的阻力位移 15.74 vs 15.79 km，SRP 3.2 vs 3.2 m。所以任何球形 SPAD 都等於某組 Cd·A／Cr·A，落在抽樣範圍內。跟姿態有關的非球形 SPAD 沒有模擬 |
| 太空天氣、曆元 | 用 CSSI 歷史檔和 2000-01-01 | 官方曆元公布後要換掉。阻力的量級會隨太陽活動差好幾倍 |
| 潮汐 | GMAT 的 SolidAndPole 疊在 EGM96 上 | GMAT 手冊提醒零潮汐的位勢模型可能重複計算永久潮汐；這一項總共 ≤ 20 m，不影響結論 |
| A 的參數 | 預設跟 B 用同一套模型，各自抽樣 | 改成 A 只受重力，差距 ≤ 40 m，hyper_far 是 0.6 km |
| 驗證程式的積分器 | 不知道 | RK89 1e-12 的數值誤差遠小於這裡量到的差距 |

在那個高度，日月的潮汐加速度跟 J2 是同一個量級，滑行時間又長，所以累積出幾百公里。

## 4. DifferentialCorrector 重瞄準

在全攝動加標稱參數下，Vary 某一棒的 VNB 三個分量，其餘棒不動。比較兩種目標：

- **定時位置對齊**（現有 `script_generator` 的 DC 做法）：預定攔截時刻 B 的位置等於 A 的位置，三個目標。
- **B 平面**：只消掉垂直於相對速度的兩個分量，三個變數對兩個目標，GMAT 的 DC 可以接受。
  沿相對速度的分量只會讓最近點早到或晚到幾秒，規則只看 d_min，所以不需要修。

點質量設計的兩個解，另外先在 J2–J4 下重瞄準一次（`_j2j4`），代表現行管線會產出的對等計畫，
這樣量到的才是 J2–J4 → 全攝動的成本。所有非零的棒都試過，下表列最後一棒的結果。

| 計畫 | 定時對齊：總 Δv 變化（向量修正量） | B 平面：總 Δv 變化（向量修正量） | B 平面重播 d_min |
|---|---|---|---|
| contest（點質量 → 全） | +27.2 m/s（27.7） | +11.3 m/s（18.8）；改第 0 棒只要 +3.7 | 0.31 km |
| contest_j2j4 | +0.21 m/s（0.23） | **+0.04 m/s（0.07）** | 0.006 km |
| official_sample | +2.80 m/s（3.29） | **+2.50 m/s（2.82）** | 0.002 km |
| hyper_far | **+271.7 m/s（351.4），最後一棒變 361 m/s**；改第 0、1 棒不收斂 | **+4.61 m/s（31.1）**；改第 1 棒是 −0.41 | 0.14 km |
| hyperbolic_smoke | +7.94 m/s（74.3） | **+0.53 m/s（2.21）** | 0.005 km |
| hyperbolic_test（點質量 → 全） | +4.36 m/s（5.69） | +2.38 m/s（5.19） | 0.018 km |
| hyperbolic_test_j2j4 | +0.10 m/s（0.11） | **+0.05 m/s（0.09）** | 0.002 km |

B 平面的版本全部在 2–6 次迭代內收斂，單次 DC 的牆鐘時間是 2–15 s。定時對齊在 hyper_far
要 37 次迭代、跑 58 s，而且會走到另一個很貴的解。hyper_far 最後一段滑行 8.4 h，推測是多圈轉移，跟 A 的相對位置
在沿軌方向接近奇異，所以定時對齊特別貴。

**重瞄準後的蒙地卡羅**（每個計畫 50 組，參數範圍同 §3）：

| 計畫 | 定時對齊後 ≤ 5 km | B 平面後 ≤ 5 km | B 平面後 d_min 中位／p90／最大 |
|---|---|---|---|
| contest、contest_j2j4、official_sample、hyperbolic_smoke、hyperbolic_test、hyperbolic_test_j2j4 | 100% | 100% | 最大 0.38 km |
| hyper_far | 94% | 94% | 0.85 / 3.71 / 14.9 km |

hyper_far 沒中的三組，B 的 Cd·A/m 是 0.12、0.23、0.30 m²/kg，都是標稱值 0.023 的 5 倍以上
（100–260 kg 卻有 12–15 m² 的面積）。Cd·A/m ≤ 0.05 m²/kg 的 39 組全部命中。

**跟 250 m/s 上限的關係。** 上面的修正量都很小，但排位賽的解由很多棒組成，拆出來的棒大多
貼著 249.99 m/s。修正要放在還有餘裕的棒上，通常是最後的微調棒；或者另外加一棒，跟前後棒
相隔至少 100 s（這種做法這裡沒有測）。定時對齊在 hyper_far 會把最後一棒推到 361 m/s，
光這一點就可以排除這個做法。

## 5. 比賽當天的流程建議

**要加「全攝動 B 平面重瞄準」。** 理由：J2–J4 解的位移就算在短任務也有 0.5–1.3 km，而我們的
設計只留 1.5 km 餘裕；任務超過幾小時就一定打偏。重瞄準只要幾 m/s，GMAT 幾十秒就跑完。

1. Python 照舊用 J2–J4 搜尋、拆棒，拿到合法的計畫。
2. 產生全攝動 GMAT 腳本（設定同 §1；開賽後換成官方曆元和官方公布的太空船參數），選一棒
   有餘裕的棒（通常是最後的微調棒），用 B 平面目標跑 DC。
3. 把修正後的 Δv 寫回固定燃燒版腳本，在全攝動下重播，確認四件事：d_min ≤ 5 km、
   攔截前 Earth-safe、每棒 ≤ 250 m/s 減安全邊際、總 Δv ≤ 3 km/s。
4. 如果太空船參數沒有公布，就在 §3 的範圍裡抽 20–50 組重播重瞄準後的計畫，看命中率。
   命中率不夠，就讓 B 少在低軌停留，或把最後一段的滑行時間縮短。

這一步要改 `src/script_generator.py`（力學模型可以切換、新增 B 平面 DC），本次研究範圍規定不碰
`src/`，所以留給後續做。驗證邏輯可以直接參考 `perturbation_gap.py` 的 `build_script` 和
`bplane_basis`。

**要問主辦單位：**

- 太空船的質量、面積、Cd、Cr，SPADFile 的內容或檔名。
- 任務曆元，它決定太空天氣與日月位置。
- 驗證程式會不會沿用我們繳交腳本裡的 `DryMass/Cd/Cr/DragArea/SRPArea/SPAD*`。如果會，
  這些參數就由我們決定，§3 的不確定性就不存在了。

## 6. 重現

從專案根目錄執行。GmatConsole 的預設路徑寫在腳本裡，也可以用 `GMAT_CONSOLE` 指定；
`MAIN_CHECKOUT` 指向放 `outputs/` 的主 checkout，只讀不寫。最多同時開 4 個 GMAT，全部用 `nice -n 10`。

```bash
uv run python scripts/research/perturbation_gap.py ladder
uv run python scripts/research/perturbation_gap.py mc --n 60
uv run python scripts/research/perturbation_gap.py retarget --mc 50
uv run python scripts/research/perturbation_gap.py retarget --mode bplane --mc 50
uv run python scripts/research/perturbation_gap.py plot
```

在 16 核機器、4 個 worker 下，ladder 約 1 分鐘，mc 約 12 分鐘，兩種 retarget（含 50 組蒙地卡羅）各約 15 分鐘。

**過程中踩到的坑：**

- 攔截後 B 常常一路鑽進大氣層。規則允許這樣（攔截後才穿越不算失格），但 MSISE 的密度會讓
  RK89 卡在最小步長、報表一直變大。每段 `Propagate` 都加了 `ShipB.Earth.Altitude = 50` 的停止條件。
- 兩艘船用不同的傳播器時，要寫 `Propagate Synchronized PropA(ShipA) Prop(ShipB)`。不寫的話
  兩艘船各走各的時間，「A 只受重力」那組的誤差會被放大成 112–224 km 的假結果。
- DC 的 `Vary` 上下限要大於原本那棒的分量。初賽的棒有 1.5 km/s，設 ±0.5 km/s 會卡在邊界、看起來像發散。
- GmatConsole 會把工作目錄切到 `bin/`，所以腳本、報表和 SPAD 檔都要用絕對路徑。
