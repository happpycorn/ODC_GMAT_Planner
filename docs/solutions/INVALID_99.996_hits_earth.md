## 為什麼這比 88.30 / 89.996 好（關鍵洞察）

計分的 **C_v = 9064 m/s 非常大 → 燃料分幾乎是平的**。從總 Δv 1,590 m/s 加到
2,500~3,000 m/s，燃料分只掉 ~0.01。所以最佳策略**不是**壓低總 Δv，而是：

1. 抵達夠早（T < ~5,800s 時間分接近滿分；本解 T=3,600s，時間分 25/25）
2. 命中 5km 內（距離分 50/50）
3. **每棒 ≤ 1500**（不吃 −10 罰分）

單棒全域最優（T=3,600s、單發 1,612 m/s）三項全滿但**單發超標** → −10 → 89.996。
只要把那一發拆成兩棒都合法，罰分消失 → **99.996**。總 Δv 從 1,612 變 1,590，幾乎不變。

## 為什麼 L-SHADE 搜尋找不到（給搜尋端的說明）

1. **罰分牆陷阱**：單發 Lambert（1,612 m/s，超標）是一個分數 89.996 的局部最優，
   旁邊就是 −10 的懸崖。族群式搜尋停在這個盆地，跨不過罰分牆到「兩棒都合法」那側。
2. **耦合窄谷**：兩棒合法解要求 burn1（部分燒）+ coast + Lambert 收尾同時滿足
   「兩棒都 ≤1500」且「早抵達」，是一條窄的耦合盆地，隨機/演化很難自己撞到。
3. **本解怎麼找的**：不是靠搜尋器，是用 **homotopy 拆分**——先抓單棒全域最優的
   衝量向量，沿同方向拆成 burn1 = f×衝量（f≈0.5 讓兩棒平衡），coast 100s，
   Lambert 收尾，再對 f/coast/抵達時間細掃取「max(兩棒) 最小」的最安全合法解。
   腳本：`scratchpad/split_two_burn.py`。

**搜尋端修法建議**：把這類「單棒最優衝量沿方向對半拆 + Lambert 收尾」的構造，
當成 `_generate_seed_candidates` 的種子丟進 L-SHADE（尤其在偵測到最優單棒超標時）。
有了種子，NLP 微調 + GMAT 驗證就能自然把這個解收進正常 pipeline，產出繳交檔。
