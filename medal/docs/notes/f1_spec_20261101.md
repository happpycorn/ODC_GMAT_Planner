# 任務 F1：引擎支援金／銅牌賽正式賽制（同時出手回合）

全程繁體中文註解與訊息，風格照現有程式碼（中文 docstring、簡潔）。不要用 emoji。

## 目標
讓 ODC_GMAT_DRL 的遊戲引擎能照 2026/10/29 正式規則跑一局：雙方**同時**在回合起點各推一發、互相看不到，
共 `rounds` 回合，每回合滑行 T_round；追方任一時刻距離 ≤ R_cap 即贏；撞地（地表）的一方輸；
最後一回合結束時逃方半長軸落在安全空域區間內才算逃方贏，否則追方贏。純二體。
**現有的回合交替模式行為必須逐位元不變**（所有現有測試照過）。

背景文件：`docs/FINAL_RULES_PLAN_20261101.md`（第一節表格）。規則摘要：
- 每回合只能在回合起點打一發瞬時脈衝；超過 ΔV_lim 不違規，等比例縮到上限照常執行。
- 總 Δv 不設上限。
- 勝負順序：攔截（Δr ≤ R_cap，任一時刻，比賽立即結束）→ 穿越地球的一方判輸 → 第 6 回合結束時逃方未被攔截且
  a ∈ 安全空域 → 逃方贏，否則追方贏。
- 半長軸用 a = (2/|r| − |v|²/μ)^-1（雙曲線時 a < 0）。
- 撞地：球形地球，高度 < 0 算穿越（半徑 RE_VAL = 6378.1363 km）。
- 兩艘的初始 epoch 可以不同：早出發的那艘先單獨傳播到晚出發的時刻，第 1 回合從那裡開始。

## 要改／新增的檔案

### 1. `game/rules.py`
新增欄位（加在既有欄位後面，預設值讓舊行為不變）：
- `turn_mode: str = "alternating"`，可為 `"alternating"` / `"simultaneous"`，`__post_init__` 驗證。
- `rounds: int = 6`：只在 simultaneous 用，≥ 1。
- `safe_sma_km: tuple | None = None`：(lo, hi) km，lo < hi；`from_dict` 收 list 轉 tuple。None = 沒有安全空域條件（撐完就是逃方贏，等同舊 timeout）。
- simultaneous 模式下 `window_sec` 就是 T_round；`burns_per_turn` 必須是 1，否則 ValueError。
- 燃料無上限：`fuel_*_mps` 允許 `math.inf`；`from_dict` 遇到 `None` 轉成 `math.inf`。`to_dict` 輸出照舊（inf 給 json.dump 會變 Infinity，Python 讀得回來即可）。
- `RuleRanges` 不動。

### 2. `game/core.py`
- 新函式 `sma_official(r, v, mu=EARTH_MU)`：a = 1/(2/|r| − |v|²/μ)，雙曲線回傳負值（能量剛好 0 時回傳 inf）。不要改既有 `sma_from_rv`。
- T_max：simultaneous 且 `t_max_sec <= 0` 時，`t_max = rounds × window_sec`，`t_max_basis = "rounds"`（優先於 boundary／periods）。
- `OUTCOME_WINNER` 新增 `"escape": "evader"`、`"sma_out": "pursuer"`。
- 新方法 `Game.play_round(dv_pursuer_eci_mps, dv_evader_eci_mps) -> dict`：
  - 只在 simultaneous 模式可用；alternating 呼叫時丟 RuntimeError。反過來 simultaneous 模式下呼叫 `play_turn`／`sub_burn`／`play_plan` 也丟 RuntimeError。
  - 雙方各自 `clip_dv`（等比例縮放、燃料）後在同一時刻 `self.t` 施加，然後雙方一起用 `coast_pair` 滑行 `min(window_sec, time_left)`，連續偵測捕獲與撞地（`crash_radius`），事件發生就停在那個時刻結束比賽（跟 `sub_burn` 一樣的寫法；`capture_mode` 仍尊重）。
  - 更新 `used`、`min_dist`、`turn`（= 已完成回合數）、`history`。
  - 最後一回合滑完且沒有事件時判終局：`safe_sma_km is None` → `"timeout"`；否則逃方 `sma_official` 在 [lo, hi]（含端點）→ `"escape"`，不在 → `"sma_out"`。
  - 回合紀錄（也就是主辦單位每回合公告的內容）至少包含：
    `round`（從 1 起算）、`turn`（= round − 1，跟舊紀錄相容）、`side: "both"`、`t`（回合起點）、
    `burns`：兩筆 `{"side", "t", "dv_eci_mps", "dv_rsw_mps", "dv_mps", "r_before", "v_before", "dv_submitted_mps", "scaled"}`（pursuer 在前、evader 在後；`scaled` 表示有沒有被縮放），
    `coast_sec`、`window_min_dist_km`、`t_window_min`、`distance_after_km`、`outcome`、`rp_after`、`vp_after`、`re_after`、`ve_after`、
    `sma_evader_km`（回合結束時逃方的 `sma_official`）。
- `Game.summary()` 在 simultaneous 時多給 `rounds_played`、`final_sma_evader_km`。
- 新函式 `take_round(game, agent_pursuer, agent_evader) -> dict`：兩邊各拿 `game.clone()`（確保互相看不到、也不能改到真的 game）呼叫 `agent.act(clone, side)`，再 `game.play_round(dv_p, dv_e)`。
- `from_snapshot` 能從 simultaneous 規則建中途狀態（t、已完成回合數 → `turn`）；加一個選填參數 `round_index`（已完成的回合數），沒給時用 `round(t / window_sec)`。
- 其餘 alternating 路徑一行都不要改語意。

### 3. 新檔 `game/initial_state.py`（官方初始狀態匯入、epoch 對齊）
- `parse_epoch(x) -> datetime`（UTC，aware）：接受 ISO 8601（`2026-11-09T00:00:00`、`...Z`、帶小數秒）、GMAT UTCGregorian（`09 Nov 2026 00:00:00.000`）、數字（當作 GMAT UTCModJulian，即 JD − 2430000.0）。格式錯誤丟 ValueError 並說明接受哪些格式。
- `align_initial_states(spec, mu=EARTH_MU) -> dict`：spec 是 dict（或 JSON 檔路徑），格式：
  ```json
  {"pursuer": {"epoch": "...", "r_km": [x,y,z], "v_kms": [vx,vy,vz]},
   "evader":  {"epoch": "...", "elements": {"sma":..,"ecc":..,"inc":..,"raan":..,"aop":..,"ta":..}}}
  ```
  每艘可用 `r_km`+`v_kms`（EarthMJ2000Eq）或 `elements`（小寫鍵，同 `game/scenarios.py` 的 orbit dict，用 `get_r0_v0` 轉）。`epoch` 可省略（兩艘都省略 = 同時出發）；只有一艘有 epoch 時丟 ValueError。
  回傳 `{"epoch": 較晚的 datetime 或 None, "pursuer": (r, v), "evader": (r, v), "propagated_sec": {"pursuer": s, "evader": s}}`：較早出發的那艘用 `physics.propagate(mu, r, v, dt, 0)`（二體）傳播 dt 秒到較晚的 epoch；另一艘 0。
- 單位防呆：|r| 看起來是公尺（> 1e6）或速度看起來是 m/s（> 100）時丟 ValueError 說明要 km、km/s（參考 `game/state_io.py` 的作法）。

### 4. 新檔 `tools/gmat_state_convert.py`（經緯高等非慣性格式 → EarthMJ2000Eq）
- 輸入 JSON：`{"pursuer": {GMAT Spacecraft 欄位...}, "evader": {...}}`，欄位原樣寫進 GMAT，例如
  `{"DateFormat": "UTCGregorian", "Epoch": "09 Nov 2026 00:00:00.000", "CoordinateSystem": "EarthFixed", "DisplayStateType": "SphericalAZFPA", "RMAG": 6871, "RA": 120, "DEC": 23.5, "VMAG": 7.2, "AZI": 90, "FPA": 90}`。
  欄位名只允許 `^[A-Za-z][A-Za-z0-9_]*$`；值只允許數字或不含引號/分號/換行的 ASCII 字串（字串值照 GMAT 寫法：`Epoch` 加單引號，其餘如 `EarthFixed`、`SphericalAZFPA`、`UTCGregorian` 不加引號）。
- 產生 GMAT 腳本：兩艘各 `Create Spacecraft` 並設欄位，`BeginMissionSequence;` 後不傳播，直接 Report 每艘的 `UTCGregorian` 曆元與 `EarthMJ2000Eq.X Y Z VX VY VZ`（兩艘可分兩個 ReportFile 或同一個；注意 GMAT Report 文字欄位的解析）。
- 用 GmatConsole 跑（路徑沿用 `tools/gmat_verify.py` 的 `GMAT_CONSOLE` 常數與環境變數；**Mac 的路徑含空白** `/Users/corn/Documents/GMAT R2026a/bin/GmatConsole`，subprocess 用 list 參數）。
- 輸出 `align_initial_states` 吃的 JSON（epoch 用 ISO 8601 UTC 字串，r_km、v_kms），寫到 `--out` 或 stdout。
- CLI：`uv run python tools/gmat_state_convert.py input.json --out initial.json [--gmat-console PATH]`。
- 腳本產生與輸出解析拆成可單元測試的純函式。

- `game_to_script` 支援 simultaneous 紀錄（`side == "both"`）：回合起點依序 `Maneuver` 兩艘各自的那一發（零向量略過），然後兩艘一起 `Propagate Synchronized` 滑行 `coast_sec`；每回合結束 Report 一列（維持「回合數 + 1 列」的慣例）。燃燒名稱不能撞名。
- `verify_game`、`gmat_truth`、`gmat_step` 在 simultaneous 下照常可用（`gmat_truth` 補滿最後窗口的邏輯沿用）。
- `main()` 依規則的 turn_mode 用 `take_round` 或 `take_turn` 跑局。
- 力學模型：`force_model="zonal"` 搭配 `gravity_degree=0` 就是點質量（Degree 0），不需要新模式。

## 實作備註（2026-11-01，Corn 上完成）
- **舊 agent 的副本**：`agents/` 裡的 agent 在副本上用 `play_turn` 模擬，simultaneous 副本會丟 RuntimeError。
  所以 `take_round`（和 `evaluation/tournament.play`）經 `game.core.round_view` 給副本：agent 有
  `simultaneous_aware = True` 時拿同賽制的 `clone()`；否則拿 `Game.alternating_view(side)`（同狀態、同 T_max、
  規則換成回合交替且輪到自己）。F2／F3 新 agent 要設 `simultaneous_aware = True`。
- **SphericalAZFPA 在 GMAT R2026a**：欄位 `RMAG RA DEC VMAG AZI FPA`，`CoordinateSystem = EarthFixed` 時 RA 就是經度、
  VMAG 是扣除自轉的速度，FPA 從徑向量起（水平 = 90°，實測 r·v = 0）。赤道測例在 EarthMJ2000Eq 的 z **不是 0**：
  EarthFixed 赤道跟 J2000 赤道差了歲差章動（2026 年約 0.15°），00:00 UTC 時 z = −12.2 km、15:00 時 −0.89 km（隨恆星時變）。
  所以測試改驗 |r| = RMAG（< 1 m）、r ⟂ v、|v − ω×r| = VMAG、z ≈ RMAG·sin(DEC)（< 25 km）。
- **GMAT Report 文字欄位**：`UTCGregorian` 輸出 `09 Nov 2026 00:00:00.000`（4 個 token），轉換工具把它放在每列最後、
  前 7 欄是 `UTCModJulian X Y Z VX VY VZ`；epoch 用 UTCModJulian 換算，再跟 UTCGregorian 對照（差 > 1 ms 報錯）。
- **地球半徑**：引擎 `physics.RE_VAL` = 6378.137 km，GMAT 預設 6378.1363 km，差 0.7 m；`physics/` 不准動，所以撞地門檻
  照引擎值。高度剛好幾公尺以內的軌跡兩邊可能判得不一樣。
- 題目產生器 `sample_final_scenario` 不在 `FAMILIES`（它要同時回傳 Rules），`sample_scenario` 沒有 `final` 分支。
