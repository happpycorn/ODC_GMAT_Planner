# `reaches_perigee()` 拿 GMAT 的事件定位交叉驗證

**日期**：2026-08-29
**腳本**：`perigee_xcheck.py`（產生 + 跑）、`perigee_analyze.py`（比對）、`perigee_exposure.py`（量漏洞寬度）

## 為什麼要做

`reaches_perigee()` 是 2026-08-28 修的那個 bug 的核心，在官方範例題目上值 **16.5 分**
（修前預設只到 73.84，修後 90.43）。但它在此之前只被 `tests/test_arc_safety.py` 的
56 組暴力交叉檢查驗過，而那個暴力檢查用的是**我們自己的傳播器** —— 等於自己驗自己。

GMAT 內建 `Propagate ... {Sat.Earth.Periapsis}` 事件定位，是完全獨立的實作。
這是驗證矩陣裡唯一還沒有外部基準的地方，偏偏它是最貴的那個函式。

## 設計

408 組案例，兩種力學模型各跑一次：

| 族 | 內容 | 目的 |
|---|---|---|
| A | 橢圓、往近地點掉（rv<0），e 0.01~0.85 × 5 個真近點角 | 主要路徑 |
| B | 橢圓、正在往外飛（rv>0），要繞快一整圈 | 另一個象限分支 |
| C | 近正圓 e = 1e-7 / 1e-4 / 1e-2 | 退化邊界 |
| D | 雙曲線 e = 1.2 / 2.0，進來與出去兩側 | `energy >= 0` 分支 |
| E | **分裂燃燒家族**：6978 km 圓軌道 + 1.3~1.6 km/s 大燒，中間軌道近地點落到 3180~3462 km（地表以下），只滑行 100 秒 | 就是那個 bug 的形狀 |
| F | **臨界傾角之外**：i = 75 / 90 / 116.6 / 135 度 | 見下方「測試設計的洞」 |
| G | 分裂燃燒，但放在官方 B 軌道的逆行幾何（6878 km, i=135）上 | E 族的逆行版 |

每族都有兩種模式：
* `MEASURE` — dt 開到 3 倍，GMAT 一定找得到近地點 → **定量**比「到近地點要幾秒」
* `BOUNDARY` — dt = m × t_pred，m 落在 1.0 附近 → **定性**比布林值，測邊界

## 結果一：純二體（驗演算法本身）

**405 / 408 完全一致。**

| 族 | n | max &#124;t_ours - t_GMAT&#124; |
|---|---|---|
| A | 75 | 8.07e-05 s |
| B | 24 | 5.72e-05 s |
| E（分裂燃燒）| 12 | **2.83e-06 s** |
| F | 108 | 3.74e-05 s |
| G | 12 | 2.47e-06 s |
| C（近正圓，退化）| 3 | 4.52e-01 s |

C 族那 0.45 秒不是分歧：e = 1e-7 時半徑變化只有 1.4 公釐，「近地點在哪」本來就沒有
物理意義，兩邊在數值噪音裡各自挑了一個點。

3 組不一致**全部是雙曲線**，而且全部是保守方向（`ours=True / GMAT=False`）：

| 案例 | dt | 真實到近地點時間 |
|---|---|---|
| D_e1.2_ta-60 | 60 s | 107.0 s |
| D_e2.0_ta-60 | 60 s | 1091.2 s |
| D_e2.0_ta-20 | 60 s | 280.2 s |

原因就寫在程式碼裡：`if energy >= 0.0: return rv < 0.0` —— 雙曲線分支**不看 dt**，
只看正在往內掉還是往外飛。回傳 True 會讓 `check_constraints` 多跑一次，是安全的方向
（可能白白丟掉合法解，不會放過危險解）。

## 結果二：J2/J3/J4（驗這個純二體判斷式守一段有攝動的弧安不安全）

`reaches_perigee` 的 docstring 寫「J2 在 100 秒尺度上改不動這個判斷」。
**在此之前那只是主張，沒有量過。** 現在量了：

**45 / 408 不一致，其中 29 保守、16 不安全方向。**

不安全方向 = `ours=False / GMAT=True`：判斷式說「這段弧不經過近地點」，攝動下實際經過了，
於是 `check_constraints` 被跳過。**16 組全部落在 F 族（i > 63.4 度）**，完全符合理論：

> J2 造成的近地點進動方向由傾角決定。i < 63.4 度近地點前進，真實通過時刻比 Kepler 預測
> **晚** → 判斷式偏保守（安全）；i > 63.4 度近地點後退，真實通過時刻比預測**早** →
> 判斷式可能漏掉一次通過（不安全）。

### 測試設計的洞（這次交叉檢查真正抓到的東西）

A / B / E 族分別用 45 / 63.4 / 45 度。**63.4 度正好是臨界傾角，近地點進動幾乎為零** ——
等於我原本只測了安全的那一側。而官方題目的 B 軌道是 **INC 135 度，就在不安全側**。
F / G 族是發現這件事之後才補的。

## 結果三：漏洞有多寬（`perigee_exposure.py`）

「跳過 `check_constraints`」不等於「沒檢查」：不經過近地點的分支改成檢查兩端半徑。
所以真正的問題是**弧的終點比真近地點高多少**。拿 GMAT 飛滿 dt 秒去量：

| | |
|---|---|
| 16 組不安全案例的最大暴露量 | **28.3 公尺** |
| `MIN_PERIAPSIS` 的安全餘裕 | RE + 100 km = **100,000 公尺** |
| 比值 | **2.83e-04** |

機制：漏掉的通過都是「差一點點」漏掉的（最多晚 20.6 秒），所以弧的終點就緊貼在真近地點
旁邊，而終點半徑是**有**被檢查的。28 公尺跟整條繳交流程的數值噪音同一個量級
（GMAT DC 的 Achieve 容許是 10 公尺，`TIEBREAK_MISS_RESOLUTION_M` 也是 10 公尺）。

## 結論

**賽前不改 `src/`。** 判斷式的失效模式已經被量化並且有界：28 公尺 / 100 公里。
真正的收穫是三件：

1. 純二體下這個判斷式跟 GMAT 的獨立實作對到 **1e-4 秒**（111 條非退化弧）—— 演算法本身是對的。
2. 雙曲線分支忽略 dt，是**已知且保守**的近似，現在有數字。
3. i > 63.4 度時 Kepler 預測會偏早，最壞 28 公尺。**賽後**若要處理，正確的做法不是把判斷式
   改成攝動版（貴），而是給 dt 加一個小的安全邊際，或無條件檢查終點半徑（現在已經有）。

## 環境坑

* `GmatConsole` 的旗標是 `--run <file>`，**不能寫成 `--run --exit <file>`** ——
  `--exit` 會被當成檔名，GMAT 印 "Script file --exit does not exist" 然後正常結束（exit code 0），
  很容易被誤判成跑成功。
* 腳本路徑一律絕對路徑（GmatConsole 把工作目錄切到自己的 `bin/`）。
* 純 ASCII。`write_script()` 裡有 `txt.encode("ascii")`，非 ASCII 會在餵給 GMAT 之前先炸。
